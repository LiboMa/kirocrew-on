HOW IT WORKS
同一条 App 对话，独立的工具会话。


父会话通过原生 MCP 分派任务，子任务完成后回到父会话。共享任务书、文件与证据，各工具保留自己的上下文和认证。


KiroCrew App
父会话→Gateway
SubagentManager→ProviderRegistry
ACP 工具会话↩


需求入口调用 KiroCrew 原生会话、上下文和聊天接口。四阶段任务由 App 内协调者通过原生 MCP 分派；本页每 2 秒读取状态。审批在 App 中处理，进度按阶段事实显示。


计划和任务文件由谁编写？
你提供需求；框架生成阶段任务指令，Kiro 生成计划、接口规格和验收测试，通过规划检查后锁定。
Claude 实现，Codex 审查，OpenCode 完成页面。这些文件是可查看的过程记录，无需你手写。修改需求时新建任务，先前的运行和 Sessions 保留。
