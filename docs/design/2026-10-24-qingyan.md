# 青岩：控制台的视觉与页面规范

负责人 2026-10-24 选定：方案一「青岩」（浅色、扁平、青绿主色），标志用方案三「四格拼合 K」。配色与页面布局参考 Sub2API 的管理后台，Logo 要方形、平面、有科技感，不要圆润效果。三个方案的对比见 [2026-10-24-redesign-options.html](2026-10-24-redesign-options.html)。

## 1. 颜色

颜色都定义在 `web/src/index.css` 里，组件只用变量（`bg-primary`、`text-muted-foreground` 等），不写死色值。

| 用途 | 浅色 | 深色 |
|---|---|---|
| 页面底色 `--background` | `#f6f8f9` | `#020617` |
| 卡片、导航、页头 `--card` / `--sidebar` | `#ffffff` | `#0b1222` |
| 主色 `--primary`（按钮、选中、链接） | `#0d9488` | `#14b8a6` |
| 选中底色 `--accent` | `#e6f6f4` | 主色 14% 透明 |
| 次要底色 `--muted` | `#f1f5f9` | `#111a2e` |

深色模式不是自动反色，每个值都单独挑过。用户的选择记在浏览器的 `octopus.theme` 里；还没选过时，跟随系统设置。主题在首次渲染前就套用，所以不会闪一下另一种颜色。

## 2. 形状与字体

- **圆角**：`sm` 2px、`md` 4px、`lg` / `xl` 6px，只有大面板用到 8px。按钮、输入框用 4px，卡片和对话框用 6px。
- **不用阴影**：控件和卡片都是平的，层次靠 1px 边框和底色区分。只有浮层（对话框、菜单、下拉框）保留阴影，因为它们确实盖在页面上面。
- **字体**：用系统字体。CSP 不允许加载远程字体。代码、Token、Worker 地址这类内容用等宽字体。

## 3. 标志

标志是四个方块拼成的 K（`web/src/components/Logo.tsx`，favicon 在 `web/src/assets/favicon.svg`）：

- 左上、左下两块青绿 `#14b8a6`，组成 K 的竖笔；
- 右上一块深灰 `#334155`，右下一块浅青 `#5eead4`；
- 两条斜切缺口组成 K 的两撇。缺口填的是背景色（`fill-sidebar`），所以在浅色和深色下都成立。

## 4. 页面结构

```
┌──────────┬──────────────────────────────────────────────┐
│ 标志      │ 页头：位置（管理 / 用户）或开发空间切换 · 新建开发 · 账户 │
│──────────┼──────────────────────────────────────────────┤
│ 工作台    │                                              │
│  会话     │  标题                          [主操作按钮]     │
│ 管理      │  一句说明                                      │
│  概览 …   │ ┌──────────────────────────────────────────┐ │
│ 我的设置  │ │ 搜索 · 刷新                        共 N 项 │ │
│  Token …  │ ├──────────────────────────────────────────┤ │
│──────────│ │ 表头                                      │ │
│ 深色模式  │ │ 行 … 行尾：图标 + 文字的操作               │ │
│ 收起导航  │ └──────────────────────────────────────────┘ │
└──────────┴──────────────────────────────────────────────┘
```

- **左侧导航**（`AppRail.tsx`）分三组：工作台、管理（只有管理员看得到）、我的设置。每组是一个有名字的 `navigation`，每个条目都是链接，可以新开标签页或收藏。底部是深色模式和收起；收起后只显示图标，这个状态记在 `octopus.rail` 里。
  - 1024px 以下，导航从页头的「打开导航」按钮打开；
  - 768px 以下，会话列表从「打开会话列表」按钮打开。
- **页头**（`TopBar.tsx`）：
  - 会话页显示开发空间切换，其他页显示「管理 / 用户」这样的位置；
  - 右侧是「新建开发」和账户菜单（修改密码、经典控制台、退出登录）。
- **分区**统一定义在 `sections.ts`，导航、页头和各页面都从这里读，不各自维护一份。

## 5. 列表页

列表页用 `components/ListCard.tsx`，样板是「我的设置 › API 与 Coding Agent 接入」（`TokensPanel.tsx`）。

- **`Panel`**：标题、一句说明，右上角放一个主操作，例如「新建 Token」。
- **`ListCard`**：工具栏放搜索、刷新，右边写数量（「共 2 枚」），下面是表格。表头用浅底色；首尾两列留 16px 边距。
- **`ListEmpty`**：列表为空时，告诉用户下一步做什么，例如「点『新建 Token』，为第一个客户端创建一枚」。被搜索过滤成空时，说明没找到什么。
- **`RowActions`**：
  - 宽屏上，常用的一两个操作以「图标 + 文字」放在行尾；
  - 其余的操作放进「⋯」菜单；危险操作标红，前面加分隔线；
  - 手机上，全部操作都收进「⋯」，不并排放按钮。
- **状态**：用小号的平面标签，例如「当前登录」「已停用」。不只靠颜色区分，标签上一定有文字。

## 6. 操作都在对话框里完成

规则见 [UI PRD](../superpowers/specs/2026-10-23-admin-settings-dialogs-prd.md) 第 3 节，这里只列要点：

- 一个对话框只做一件事。标题用动词，提交按钮写出结果，提示条用同一个词，例如「重新生成 Token」→「重新生成」→「已重新生成 Token X」。
- 危险操作先确认，并写清后果；不可撤回的操作，要求输入名称确认。
- 一次性秘密（新建或重新生成的 Token）只在那一屏显示一次，配「复制」和「我已保存」。
- 动画只用来表达变化：
  - 新增或修改的行高亮一次，删除的行淡出（`rowMotion.ts`）；
  - 系统设置为「减少动态效果」时，一律不播放动画。
