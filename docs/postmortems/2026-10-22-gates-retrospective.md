### B. 每个任务的门禁（失败 → 阻断 → 协调者诊断 → 返工）

D37 起每个任务都过同一组门禁。D57 已把不少降为只提示：交接缺失、结论格式、审查版本不符、改动范围、基线测试、无改动等。

今天仍会阻断的：
- **任务没跑完**（`native_completed`）；
- **工具或模型与配置不符**（`identity_match`）；
- **执行者或审查者写了 `blocked` / `changes_requested`**（`outcome_pass`）：所有任务、所有阶段都一样，这就是「每次审查都要过门禁」的来源；
- **审查改动撤不回**（`review_bound` 的少数情形）；
- **必过检查失败**（`checks_pass`：你自己写的检查默认全部必过；规划者写的只有引用需求原文的才必过）；
- **Evaluator 判不通过**（`evaluated`；每个有实现 / 交付任务的会话都会自动追加一个 Evaluator 任务）；
- **规划结果未通过校验**；
- **推荐方案自动修正一次后仍无效**；
- **疑似密钥**（`no_secrets`）：**这是安全底线，按负责人的规则保留。**

### C. 限额与预算

- **自动纠错**：最多 2 轮、4 次重试、720 分钟；超过就停下。
- **看门狗**：30 分钟没有进展，或单次任务超过 170 分钟，就停止并重试。
- **任务数上限**：12 个。原来是 8 个，正是它导致 9 个任务的推荐被判无效（D66）。
- **重新规划**：只有 1 次，合同类问题另有 2 次。
- **审查独立性**：审查不能用作者的工具；提交的工作流违反时直接拒绝。
- **排队**：执行环境内存不足时排队（KiroCrew）；并发上限默认不开。
- **停用 OpenCode**：指定它的任务会停下（这是负责人的决定）。

### D. 界面与 Agent 指令里的确认

- **控制台**：
  - 删除会话要输入完整会话 ID；
  - 设为共享环境要确认；
  - 停用用户、归档 Team、删除凭证各有一次确认。
- **Skill 与 MCP**：要 Agent 先征得你同意的动作很多，包括批准工具调用、确认验收、发布、开启自动发布、分配执行环境、换工具、补充说明、同步、推送基线分支、停止 / 关闭 / 删除。

- **D57 Task 12「有提示就不自动发布」**：一旦实现，任何一条提示都会让自动发布等你确认。
- **D57 T8「安全拦截」状态**：属于安全底线，是负责人自己的规则。
- **D69「设计阶段末把关一次」**：属于减少关卡的方向，但仍新增了阶段末这道关。

## 3. 根因（我的问题）

1. **默认倾向「停下来问」**：
   - 我把「可控」理解成「多一个确认」，而不是默认把流程跑完、出了问题再停。
   - 每加一项能力，我都顺手配一道关卡。
2. **改默认值时没讲清体验代价**：D55 的问题我写成二选一的技术选择，没有写「这意味着每个会话都要你点一次」。
3. **只看单个功能，不看总的摩擦**：
   - 每道关卡单看都有理由；
   - 叠起来，就是处处要确认、处处会阻断、处处进纠错循环。
4. **修了一半，拖着没上线**：
   - D68 只改了默认值，保留了显式确认与规则；
   - 提交后没有及时部署，部署前还带着一个启动即报错的 bug；
   - 结果你在 EC2 上又被拦住。
5. **Agent 指令也在教 Agent 多问**：Skill 与 MCP 里大量「先征得用户同意」，Coding Agent 因此频繁打断你。

## 4. 以后的规则（已记入长期记忆）

- 任何会让会话停下、等人、要确认、阻断任务进入纠错循环的关卡，以及把默认值改得更容易停下的改动，**都先经负责人确认**，并写清体验代价。
- **默认一律跑完。** 只有安全底线（拦截密钥泄露）默认阻断。
- 去掉负责人不满意的关卡，不需要再确认。
