# KiroCrew ON 宣传片

根据[白皮书](../WHITEPAPER.md)做的一支约 105 秒的宣传片（1920×1080，30 fps，中文配音，字幕画在画面里，另附 SRT）。

**主线是「一夜」**：右上角的时钟从傍晚 18:40 走到次日 09:30，天色随之从黄昏、深夜变到清晨。片中的会话 run-44dc 是线上实例里的一次真实调研会话：20:55 创建，审查打回 5 处能被源码证伪的错误，次日 09:11 全部通过。

| 场景 | 讲什么 |
|---|---|
| 合上电脑 | 本机的 Agent 合上电脑就停，「做完了」只是自述 |
| 四个摩擦 | 人得守着、自己批改自己、失败了要人接、成果困在一台电脑上 |
| 标志 | KiroCrew ON，7×24 在线的多 Agent 研发协作空间 |
| 说一句话 | 在 Claude Code、Kiro CLI、Kiro IDE、Codex 里提交，任务交给后台 |
| 分工互审 | Kiro 规划、Claude Code 实现、Codex 审查、Evaluator 验收，交接文件在任务之间传递 |
| 平台判定 | 门禁逐项核对，Evaluator 打回，协调者退回返工，第二次全部通过 |
| 一夜之间 | run-44dc 的真实修订时间线与 F1–F5 |
| 回来 | 控制台里的规划、执行轨迹、证据、预览、报告、续作（线上截图） |
| 接力 | Team 里共享与接手；自托管在你的 AWS 账号，每人一个执行边界 |
| 上线一个月 | 140 个会话、411 个任务、81% 完成、80 个会话多 Agent 协作 |
| 收尾 | 把信任交给平台，让 Agent 放手去做 |

## 文件

| 文件 | 内容 |
|---|---|
| `script.json` | **唯一的脚本**：每个场景的配音文本、字幕、画面时钟与最短时长 |
| `promo.html` | 画面：各场景的 CSS 动画都暂停，由 `seek(t)` 定位到第 t 秒 |
| `render.mjs` | 配音、排时间线、逐帧渲染与编码 |
| `KiroCrew-ON-宣传片.mp4` · `.srt` | 成片与字幕 |

## 重新生成

在仓库根目录执行，需要 macOS（`say` 配音）、Google Chrome、ffmpeg，以及 `web/node_modules`（`npm --prefix web ci`）：

```bash
node docs/whitepaper/video/render.mjs                    # 成片与字幕，约 5–10 分钟
node docs/whitepaper/video/render.mjs --stills 3,20,60   # 只出这几秒的静帧（./stills，不入库），用来检查画面
node docs/whitepaper/video/render.mjs --no-music         # 不加垫底音乐
```

- 每个场景的时长随配音长度自动排定，至少为脚本里的最短时长。字幕按句号、分号断句，超过 26 个字的句子再在逗号处拆开，按字数分配时间。
- 配音用 macOS 的 Tingting。字幕写「7×24」的地方，配音读作「全天候」。
- 垫底音乐是渲染时合成的两个和弦缓慢交替，音量远低于配音；最后整体按 −16 LUFS 做响度标准化。
- 同一份脚本每次渲染的画面都相同：帧是按固定时间点逐帧截取的。
