# 恢复阶梯第 3 期：会话预算（D42，M2）

## 1．目标

M2 的验收要求「故障注入在预算内自动恢复；预算耗尽时给出原因与操作」，设计 §8.1 要求「在报告中显示消耗」。现状：

- 协调者轮数 `max_cycles` 按会话的全部纠错记录计（含手动诊断与已取消的），**从不重置**：用户续作之后，同一会话不再自动纠错，除非调大轮数；
- 自动重试（D34 瞬时重试、D39 看门狗重试）每条 Attempt 链一次，但会话内**不设总数**；
- 没有时间预算；控制台、MCP 与报告看不到消耗。

本期：会话的自动纠错预算由三项组成——协调者轮数、自动重试次数、时长——从会话开始或用户最近一次续作 / 手动诊断起计算；用完时写明哪一项用完，
控制台、MCP 与报告显示消耗。第 2 期（另行设计）：L4 等待与条件满足后自动恢复。

## 2．已确定（负责人方向：开发质量与 Agent Harness 优先，非必要不确认）

| 编号 | 决定 |
|---|---|
| B1 | 预算只限制**自动**的恢复（瞬时 / 看门狗重试、协调者诊断），不限制计划内的任务：完成优先，正在运行的任务不因预算被停止。 |
| B2 | 预算窗口从会话创建或用户最近一次「续作」/「请求诊断」起算：用户的这两个操作就是对更多自动工作的授权。手动诊断的那一轮不计入。 |
| B3 | 新设置的默认值不保存（与 `idle_minutes` 等相同）：`max_retries` 默认 4（0–20）、`budget_minutes` 默认 720（30–4320）。 |
| B4 | 重新规划仍是每个会话一次（D41 R2），不随续作重置。 |

## 3．设计

### 3.1 计算（`recovery.budget(db, run)`）

- `since` = 快照 `budget_since`，没有时为会话创建时间（已有会话按创建时间计）；
- `cycles`：`since` 之后创建的、非手动（`context.manual` 不为真）的纠错记录数 / `max_cycles`；
- `retries`：`since` 之后创建的、带 `transient_retry_of` 的 Attempt 数 / `max_retries`；
- `minutes`：`now − since`（分钟，向下取整）/ `budget_minutes`；
- `exhausted`：第一个用完的一项（`cycles` 达到上限、`retries` 达到上限或 `minutes` 超过上限），没有为 `None`。

### 3.2 使用

- **自动重试**（D34 瞬时、D39 看门狗）：`retries` 达到上限或 `minutes` 超过上限时不重试，按「已是自动重试」处理——交给协调者诊断（若诊断仍有预算）。
- **协调者诊断**（`schedule`，非手动）：`cycles` 达到上限或 `minutes` 超过上限时不诊断，会话 `blocked`。
- **续作**：快照 `budget_since = now`（与续作的其他改动在同一事务中）；**请求诊断**：同样重置，所建的这一轮为手动，不计入。

### 3.3 可见

- 纠错摘要（`recovery`）增加 `budget: {since, cycles: {used, limit}, retries: {used, limit}, minutes: {used, limit}, exhausted}`；
  `used`（全部纠错记录数）不变。
- 会话 `attention`：预算用完时 `action` 末尾写明哪一项（「自动纠错已达到 2 轮上限」「自动重试已达到 4 次上限」「自动纠错时长已超过 720 分钟」）
  与「续作会重新计算预算，也可在续作时调大」。
- 控制台纠错记录的标题下一行：「预算（自上次续作起）：纠错 1/2 轮 · 自动重试 0/4 次 · 35/720 分钟」，用完的一项标出。
- MCP 精简状态的 `recovery.budget`；报告的纠错一节写同一行。
- OpenAPI 与 MCP 的 `RecoveryPolicy` 增加 `max_retries`、`budget_minutes`；顺带更正 `attempt_minutes` 的默认值（170，原写 240）。

## 4．测试与验收

- **本机**：
  - 设置的校验与默认值不保存；
  - `max_cycles` 用完 → 续作后同一会话的下一次失败再次被诊断；手动诊断不计入、并重置窗口；
  - `max_retries: 1`：两个任务先后瞬时失败，第一个自动重试，第二个直接进入诊断；看门狗重试同样受限；
  - `budget_minutes` 超过 → 不重试也不诊断，`blocked`，`attention` 写明时长用完；
  - 已有会话（无 `budget_since`）按创建时间计；摘要、MCP、报告与控制台显示消耗。
- **EC2**：一个审查必然失败的会话，`max_cycles: 1`：一轮后 `blocked` 并写明轮数用完；续作后再次自动诊断（消耗显示从 0 起）。
