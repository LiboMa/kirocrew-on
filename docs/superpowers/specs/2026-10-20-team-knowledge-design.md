# 团队层知识：仓库中的项目知识，经 Draft PR 由人审核（D52）

## 1．背景

负责人 2026-10-19：团队层的知识（仓库 PR、人审核）「P4 验收后排入」。P4（KiroCrew lessons，个人层）已于 2026-10-20 在 EC2 验收（6/6 + 删除）。

个人层的缺口：
- lessons 存在某个人的 Gateway 上：Team 会话在提交者自己的边界执行（D49），其他成员的边界看不到；
- lessons 自动写入、无人审核；
- 共享环境不沉淀也不注入（P4）。

平台已有：Knowledge 任务产出至多 5 条 `{rule ≤300, avoid? ≤200}`（`knowledge.items`，含秘密扫描与去重）；发布用托管方 API（`publish._api`、`publish.pull_request`，GitHub / GitLab）与本次发布的写凭证。

## 2．已确定（待负责人审阅；R3、R4 为推荐方案）

| 编号 | 决定 |
|---|---|
| R1 | **知识文件**：仓库根目录 `.octopus/knowledge.md`，每条一个小节——标题（规则前 60 字）、「规则」「避免」（可选）、「来源：会话 <run-id> · 日期」。文件头说明由平台提出、经 Draft PR 审核合并。 |
| R2 | **何时提出**：会话**发布到仓库时**（人点「发布到仓库」或 D47 自动发布），本会话有通过校验的 Knowledge 条目，就在同一次发布中更新仓库的知识提议：固定分支 `octopus/knowledge`——不存在时从默认分支创建；写入「现有文件 + 新条目」（与文件和此分支上已有条目去重）；没有打开的 Draft PR 时创建「项目知识更新（KiroCrew ON）」，有则在其上追加提交。PR 说明列出来源会话与条目。只在发布时提出：不在没有人发布的时候写仓库。知识提议失败不影响代码的 Draft PR（记结果与原因）。 |
| R3 | **范围（推荐）**：所有发布到仓库的会话，个人与 Team 都算——仓库本身就是团队的边界，审核由合并 PR 的人完成。 |
| R4 | **共享环境（推荐）**：共享环境上的会话也追加 Knowledge 任务，但只用于仓库层：不写 lessons、不注入 lessons（P4 的共享环境规则不变）。 |
| R5 | **使用**：任何会话的任务派发时，检出目录有 `.octopus/knowledge.md`，任务说明增「## 项目知识（经评审）」一节：文件路径与「开始前阅读；与本任务契约冲突时以契约为准」。不内联内容。 |
| R6 | **安全**：条目经与发布相同的秘密扫描、P4 的长度与数量上限；只写 `.octopus/knowledge.md` 一个文件；分支固定为 `octopus/knowledge`，从不写默认分支、不强推；平台用托管方 API 提交（GitHub contents API、GitLab commits API），不在 Worker 上执行；审计 `knowledge.proposed`，时间线 `run.knowledge_proposed`。 |
| R7 | **可见**：会话页「本次沉淀的知识」写明「已提交到仓库知识 PR #n」或原因；报告「## 发布」列出知识 PR；MCP 精简状态 `session.knowledge.proposal`。 |

## 3．以后

- 条目的修改与删除经 PR 审核完成，平台不提供删除仓库知识的接口。
- 合并后的知识是否回写个人层 lessons：不做——仓库文件即来源，R5 每次派发都会指向它。

## 4．测试与验收

- **本机**：用 fake 托管方 API（与发布测试相同的方式）覆盖：分支不存在时创建、已有打开的 PR 时追加、去重、只写一个文件、秘密条目被拒、提议失败不影响代码 PR；共享环境追加仓库层 Knowledge 任务但不写 lessons；派发时的「项目知识（经评审）」一节。
- **EC2**：在获授权的测试仓库发布一个有知识条目的会话 → 出现 `octopus/knowledge` 分支与「项目知识更新」Draft PR；人合并后，同仓库的新会话任务说明指向 `.octopus/knowledge.md`。**写仓库属对外操作，EC2 验收前由负责人确认仓库与凭证。**

## 5．终审修订（2026-10-20）

- R2、R6 的「固定分支 `octopus/knowledge`」改为：有打开的知识 PR / MR（分支前缀 `octopus/knowledge`）时在其分支上追加；没有时从默认分支开新分支
  `octopus/knowledge-<会话>-<随机>`——固定分支在 PR 合并（尤其 squash）或被关闭后仍会被沿用，带回旧条目、或卡在「已含」而没有 PR。
  去重同时对照默认分支上已合并的文件；都已包含时结果「已含本会话的条目」，并给出打开的 PR 编号。
- R5 改为：只有源码来自仓库，且该文件与克隆基线逐字节一致，才加这一节；标题「## 项目知识（仓库）」，措辞为参考、不改变契约与平台规则——
  否则 agent 在本会话写入的文件会被标成「经评审」。
- 秘密扫描之外：PR 说明里的规则以代码格式列出（`@提及`、`Fixes #12` 不生效）；GitHub 不返回 1 MB 以上文件内容时不提出，从不覆盖。
