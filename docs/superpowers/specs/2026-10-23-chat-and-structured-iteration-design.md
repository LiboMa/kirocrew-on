# 在 KiroCrew 聊天里直接和父会话对话，也能回到平台续作（D73）

状态：设计，待负责人确认；确认前不实现。

负责人原话（2026-10-23）：
- 「让用户可以继续在 KiroCrew chat sessions 中继续聊天；如果不想聊了，也可以通过目前最新的状态，继续由 KiroCrew ON 这个平台记录的 Session 继续创作。」
- 「我们可能不需要撤回什么，只需要找到相关的历史。」
- 「我说的是，用户在 KiroCrew 的 chat 里直接和父进程对话吧？而不是再造什么接口？？」

上一版设计新增了一整套接口（`/chat/activity`、`/absorb` 等），把事情做复杂了，已经删掉。D72 的 `@任务` 也不再需要：用户直接对父会话说即可。

## 1. 做法

用户在会话页点「在 KiroCrew 中打开」，进入这个会话的父会话 `octopus-run-<id>`，直接和父会话的 Agent 对话。用的是 KiroCrew 原生的聊天，不新增任何接口。

- **历史已经在聊天里。** 平台在聊天里写了两类说明：建立会话时的一条（含工作区路径），和每个任务结束时的一条结果说明（a183d84 之后仍然有）。
  Agent 从这些历史里找，不需要恢复每个任务的回复。
- **想接着干就直接说。** 例如「把首页标题改成……」「再补一段测试」「总结一下现在的状态」。
  Agent 可以自己改工作区里的文件，也可以按 KiroCrew 原生的方式派子 Agent。
- **不想聊了，就回到平台续作。** 平台从工作区现在的状态继续，也就是聊天改过之后的状态。
  想先归纳一下，就在聊天里让 Agent「总结当前状态与下一步」，把它写进续作的需求。

## 2. 要改的只有两处

### 2.1 父会话 Agent 的提示

现在父会话的 Agent 是「Owner 观察员」，提示要求它只解释、不派发、不改源码（`octopus/prompts.py` `COORDINATOR`，以及 Worker 写进父会话的
`OBSERVER_CONTEXT`）。改为「会话协作者」：

- 回答关于本会话的问题，以聊天里平台写的说明、交接文件和工作区为准；
- 用户要求时，可以直接修改工作区（路径在第一条说明里），或派子 Agent（`poc-kiro` / `poc-claude` / `poc-codex`，`cwd` 为工作区）；
- 平台正在执行任务时先不动手，告诉用户等平台停下，或者先在控制台停止；
- 不推送、不建 PR / MR、不改 `.octopus/` 下的平台文件、不读凭证——这条和平台派的子 Agent 相同；
- 用户要回到平台时，可以按「做了什么、做了哪些决定、还剩什么、需求有没有变」帮他总结。

`COORDINATOR` 在 Gateway 的 Agent 模板里，改它要重启 Gateway。`OBSERVER_CONTEXT` 只对新会话生效。两处一起改，随某次部署重启。

另外，在派发白名单里去掉已停用的 OpenCode，免得聊天里的 Agent 派它（`composition/templates.py`，同一次重启）。

### 2.2 续作时保住聊天里的改动

平台下一次派发前，工作区里如果有不在候选提交里的改动（聊天里改的），要先把它们提交成新的候选。否则：

- 下一个任务是审查时，审查结束后的「放回」会把它们当成审查的改动还原（`sources.rewind` 还原相对候选有改动的已跟踪文件）；
- 下一个任务是实现时，它们会混进那个任务的候选，记到那个任务名下。

做法复用已有的代码，不新增对外接口：

- 续作时，平台用 Worker 现有的 `/candidate`（`commit`）把工作区现状提交为新的候选，记为一次「对话中的改动」尝试。
  这一步与 D58「本地同步」相同：挂在最后一个写代码的任务上，照常做秘密检查、跑检查命令，在修订历史里记一条。
- 之后的任务按新候选重新执行，审查针对新候选。

## 3. 弊端

| 问题 | 怎么处理 |
|---|---|
| 聊天里的改动，在续作之前没有经过平台的检查与审查 | 续作时做秘密检查、跑检查命令，审查重跑；只聊不续作的改动不会被发布（发布要求门禁通过） |
| 平台在跑时，Agent 仍可能动手 | 提示要求它先不动手；最坏情况是一次尝试的候选里混进聊天的改动，修订里看得到 |
| 聊天里每条消息都会让 Agent 跑一轮 Kiro | 这是用户主动发起的，平台自己不额外触发轮次 |
| 原生登录覆盖整个 Gateway（K03），聊天消息分不清是谁发的 | 续作由点续作的人发起，平台记为此人 |
| 改提示要重启 Gateway | 随下一次部署一起做；旧会话的 Agent 仍按旧提示行事，只回答、不动手 |

## 4. 验证（先做）

在一个已完成的测试会话上：

1. 在原生聊天里问「做到哪了、改了什么」，看 Agent 凭聊天里的说明能否答准；
2. 让它改一个文件、再派一个 `poc-claude` 子 Agent 改另一个文件；
3. 让它总结当前状态；
4. 回到控制台续作，确认两处改动进入新候选、审查针对新候选、修订历史里有「对话中的改动」。

第 2 步需要 Agent 能动手。可以在测试会话里先用一条用户消息说明「这是测试，允许你修改」，不用为此先改提示。
