# M3-5 控制台：服务端过滤、全文搜索、分页与代码改动（D56，设计稿）

日期：2026-10-21。负责人：「继续完成 M3、M4、M5」。范围是看板上的 M3-5，以及 M3-3 剩下的「搜索」。

## 1. 现状与差距

MVP-RELEASE §7 第 5 项与验收 3：控制台可按状态、仓库、分支、阶段、工具、客户端、提交者、时间过滤，可全文检索；服务端分页；详情覆盖 Pipeline、门禁、Attempt、恢复记录、事件、diff、报告。

| 要求 | 现在 | 差距 |
|---|---|---|
| 过滤 | `GET /v1/runs` 只有 `status`、`q`、`limit`；控制台拉取空间内全部会话的精简列表，按状态分组与关键词在浏览器里筛 | 仓库、分支、阶段、工具、客户端、提交者、时间没有过滤；状态分组只在浏览器 |
| 全文搜索 | `q` 只匹配会话 ID、名称、需求原文 | 规划补全、任务名称与说明、最近一次结论与错误不在检索范围 |
| 分页 | 一次返回全部（`limit` 只截断） | 没有游标，没有总数 |
| 详情 | Pipeline、门禁、Attempt、恢复、事件、报告都有 | 没有代码改动（diff）；只有修订之间的需求与任务对比 |

## 2. 列表接口

`GET /v1/runs` 新增参数，全部可选，可组合（与）：

- `space`：`personal`（个人空间）或 Team ID。
- `status`：一个或逗号分隔的多个状态；`lifecycle`：`open` / `closed`。控制台的「进行中 / 需处理 / 已完成 / 已关闭」由这两项表达，平台不另设分组名。
- `repo`：仓库，按 `主机/所有者/仓库` 小写比较（D55 `policies.repo_of`，三种写法同一结果），包含即命中；新建项目不命中。
- `branch`：会话的源码 ref 或发布分支，包含即命中。
- `stage`：当前阶段，即第一个未验收任务的类别（`plan` 表示规划任务；`implement` / `review` / `test` / `deliver` / `design`），全部验收为 `done`。
- `tool`：任一任务使用的工具。
- `client`：Request 的来源客户端（D55）；没有 Request 的旧会话不命中。
- `submitter`：提交者的用户名或用户 ID。
- `since` / `until`：创建时间，Unix 秒或 `YYYY-MM-DD`（UTC 当日起止）。
- `q`：全文。会话 ID、名称、需求、规划的意图与补全、各任务名称与说明、各任务最近一次结论的摘要与错误；多个词以空格分隔，全部命中。
- `page=1`：分页模式，返回 `{"items": [...], "next": "<游标>" | null, "total": <命中总数>}`；`cursor` 取上一页的 `next`，`limit` 默认 50、最多 200。不带 `page` 时保持现在的数组返回，旧客户端不受影响。

顺序：最新创建的在前；游标是不透明字符串（创建时间与 ID），翻页时新建的会话不会让已翻过的条目重复。

**实现方式（我的取舍）**：沿用现在逐行核对访问权限的扫描，在扫描中按上面的条件筛。EC2 现有一百多个会话，扫描在毫秒到百毫秒级；不建 FTS 索引（迁移与同步成本高于现在的收益）。会话超过数千个时再建索引，记入 BACKLOG。

## 3. MCP

`octopus_runs` 增加 `space`、`repo`、`tool`、`client`、`submitter`、`since`、`stage` 参数，透传给列表接口；`q` 随之成为全文搜索。返回仍是精简的 `{items, more}`（M3-3）。

## 4. 控制台

- 侧栏列表改为服务端查询：搜索框（输入停顿 300 ms 后查询）、状态分组按钮、「筛选」面板（仓库、分支、阶段、工具、客户端、提交者、创建时间起止）。已选的条件以可移除的标签显示在列表上方，并写进地址栏，便于分享和刷新后保留。
- 分页：首页每 10 秒刷新；列表底部「加载更多」取下一页。标签页上的数字是服务端返回的总数。
- 选中的会话不在已加载的列表中时，按 ID 单独读取它；读不到才提示「该 Session 已不可访问」。
- 空状态与「没有符合条件的会话」照旧；有筛选条件时多一个「清除筛选」。

## 5. 详情：代码改动

- Worker 的 `/candidate` 新增 `mode: diff`：给定候选 SHA 与它的上一个候选（或会话基线），返回 `git diff --stat` 与统一 diff；超过 200 KB 或 4000 行截断并标明。只读，不移动分支，候选之外的工作区内容不读。
- 平台：`GET /v1/runs/<id>/attempts/<attempt>/diff`（Read scope，访问检查与会话详情相同；管理员读他人会话的写审计）。没有候选的 Attempt 返回 404 `no_candidate`；旧 Worker 返回 409 并说明需要升级执行环境（D53：提示只写原因）。
- 控制台：任务的 Attempt 详情多一个「代码改动」折叠区：文件列表（增删行数），点开某个文件看它的 diff；截断时写明。报告不嵌入 diff（报告已有候选 SHA 与文件数）。

## 6. 不做

- 控制台的批量操作；「复制 CLI 命令」等 M3-2 用户 CLI 之后再加。
- FTS 索引与跨会话的事件检索。
- diff 的逐行评论。

## 7. 验收

- 控制台按每一种条件（含组合）与全文都能找到对应会话；翻页不重复、不遗漏；总数与条件一致。
- 一个改代码的会话，在详情中看到每次候选的文件列表与 diff。
- `octopus_runs` 按仓库、客户端、提交者过滤结果与控制台一致。
