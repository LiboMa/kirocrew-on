# 发布：需求要求或前端开启时自动发布 Draft PR，否则人工确认（D47）

## 1．背景

EC2 `run-361cd491…`（负责人 2026-10-16 反馈）：需求要求提交 PR。KiroCrew 规划了一个「提交到 main」的任务，但 Agent 手里没有仓库写凭证（设计如此），
任务因认证失败停下，会话 `blocked`。「需要处理」又写着「在原生 KiroCrew 处理权限」，看起来像凭证出了故障，实际上用户只需要点「发布到仓库」。

负责人方向：**用户明确说要提 PR 时，就自动为该会话分支提交 PR；或者在前端控制是否自动提交；否则默认需要人工审批。**

## 2．已确定

| 编号 | 决定 |
|---|---|
| P1 | 会话的发布策略 `publish: {auto, branch?, title?}`：`auto` 为 true 时，会话**完成**且满足发布条件后，平台以会话创建者的身份自动发布（推送 `octopus/<run>` 分支并创建或沿用 Draft PR / MR，与「发布到仓库」相同的核对：写权限凭证、只推已验证候选、秘密扫描、不推默认分支）。 |
| P2 | 设定来源：启动时的 `publish`（API / MCP / 控制台向导的「完成后自动发布 Draft PR」开关）；会话页随时可开关；需求中明确要求提 PR / MR 时由 KiroCrew 规划者标注（计划 JSON 顶层 `publish: {quote}`），平台据此开启——用户在启动时明确设置的优先。 |
| P3 | 默认 `auto` 为 false：会话完成后由人确认发布（不变）。 |
| P4 | 自动发布失败（没有写凭证、改动未通过审查、发现秘密、远端冲突等）不改变会话的完成状态：记一次结果，「需要处理」写明原因与操作（补凭证后点「发布到仓库」）；同一版本只自动尝试一次。 |
| P5 | 规划者不安排推送 / 建 PR 的任务（D46 P1 已写入规则）；规划结果中仍出现时记说明。任务因尝试推送失败时，「需要处理」说明「Agent 不能推送或创建 PR，发布由平台完成」，不再误导为权限问题。 |

## 3．可见

- 会话页：发布区显示「完成后自动发布：开 / 关」开关（有发布权限的人可改）与自动发布的结果（链接或失败原因）。
- 时间线：`run.publish_auto`（「自动发布 Draft PR」/「自动发布未完成」）。
- MCP：`octopus_start.publish`、精简状态的 `publish_policy`；Skill：需求要提 PR 时传 `publish: {auto: true}`，否则完成后询问用户再 `octopus_publish`。

## 4．测试与验收

- **本机**：`auto` 时完成即发布（推送与 PR 调用各一次）；默认不发布；规划者标注 `publish` 时开启、用户显式关闭时不开；
  发布条件不满足时不改变完成状态并写明原因、不重复尝试；会话页开关；推送失败的任务的提示；规划结果中的推送任务的说明。
- **EC2**：公开测试仓库上 `publish: {auto: true}` 的会话完成后自动出现 Draft PR（需负责人同意在测试仓库建 PR）。
