# 恢复阶梯第 2 期：重新规划（D41，M2）

## 1．目标

M2 验收要求「换工具与重规划在记录和报告中可见」。换工具已有（D38），重规划没有：计划本身有问题时（任务拆分不当、缺少步骤、
顺序错误、任务目标与需求不符），协调者只能在错误的任务上反复重试或返工。

本期：协调者可以决定 `replan`，平台请 KiroCrew 规划剩余的工作，替换失败的任务及其后的任务，已验收的任务保留。

## 2．已确定

| 编号 | 决定 |
|---|---|
| R1 | 由协调者判断是否需要重新规划（`replan`）；平台只核对次数与会话类型，不自行决定。 |
| R2 | 每个会话至多重新规划一次；重新规划消耗一轮纠错。 |
| R3 | 替换的任务行被删除，其 Attempt 留作历史（`attempts.task_id` 不受约束）；修订历史保存替换前的计划。新任务的 ID 不与任何已有 Attempt 的任务 ID 相同，历史不混在一起。 |
| R4 | 重新规划由一个 Kiro 任务（`replan-1`）完成，与首次规划相同的方式校验并追加任务（`planning.expand`）。 |

## 3．设计

### 3.1 协调者

- 决定的动作增加 `replan`：`{"action": "replan", "reason": "…", "instructions": "重新规划的要求"}`，不需要 `target_task_id`。
- 提示：计划本身有问题时用 `replan`；实现、测试、契约或门禁的问题仍用 `retry` / `rework`，工具本身的问题用 `switch_tool`；
  已重新规划过（上下文 `environment.replanned`）时不能再用。
- 平台核对（不通过时会话 `blocked` 并写明原因）：会话未重新规划过；不是工作流设计会话；失败的任务不是规划任务本身。

### 3.2 生效

1. 失败的任务及其后的任务（`ordinal ≥ 失败任务`）删除，变更记录 `task.replaced`（列出 ID 与名称）。
2. 在失败任务的位置插入 `replan-1`（Kiro，`model: auto`）：提示含
   - 用户需求与规划补全的需求（`intent` / `summary`）；
   - 已验收任务的名称、类别与结论摘要（D40 的交接格式）；
   - 被替换的任务（名称、类别）、失败的原因、协调者的原因与要求；
   - 「只规划剩余的工作，不重复已完成的任务；1–6 个任务；每个任务给出契约」。
3. 快照记 `replan: {task: "replan-1", applied: false, replaced: [...], reason, recovery: <轮次>}`；修订记一次 `recovered`
   （「自动纠错：重新规划，替换「a、b」（原因）」）。
4. `replan-1` 验收后，与首次规划相同：`planning.expand` 校验并在其后追加任务；新任务 ID 避开所有已有 Attempt 的任务 ID；
   快照 `replan.applied = true`、`replan.tasks = [...]`；修订记一次 `planned`（「重新规划：追加 N 个任务」）。
   规划结果未通过校验时 `replan-1` 判为 `blocked`（`failure_type: contract`），照常进入诊断。

### 3.3 可见

- 任务的映射来源（`mapping`）：`replan-1` 为「平台：重新规划（Kiro）」，其后追加的任务为「KiroCrew 重新规划」。
- 控制台纠错记录：`replan` 一轮写「重新规划」与被替换的任务；概要「已安排重新规划」。
- 报告的纠错记录写 `replan` 与原因；计划表显示新的任务（被替换的任务见修订历史）。
- MCP `recovery.latest.action` 为 `replan`。

## 4．测试与验收

- **本机**：协调者给出 `replan` → 失败任务及其后任务被替换、`replan-1` 派发且提示含已验收任务与失败原因 → 其结果追加新任务 → 新任务执行，会话完成；
  第二次 `replan` 被拒；新任务 ID 与旧 Attempt 不冲突；工作流设计会话与规划任务失败时拒绝；修订历史、映射来源、纠错记录可见。
- **EC2**：一个任务拆分明显不当的会话（例如「只写文档」的任务承担了实现需求，审查以未实现为由失败），协调者给出 `replan` 后完成；
  协调者也可能判断为返工——如实记录。
