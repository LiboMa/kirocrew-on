# Agent Prompt P1：一致性与正确性（D46 P1） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修掉 Agent 提示中互相矛盾、缺失与冗长之处（D46 §2 的 A、B、C、D 各项），不改变角色模型。

**Architecture:** 共同原则（`prompts.py`）收敛并去掉过时内容；规划提示的规则抽成一份，首次规划与重新规划共用；Worker 的派发外壳按任务性质给出结尾与交接要求；
纠错要求只给被安排修复的任务且摘要化；协调者上下文不再内嵌两次；内置模板补 `kind`、验收与一致的结论用法。

**Tech Stack:** Python 3 标准库。

**Spec:** `docs/superpowers/specs/2026-10-16-agent-prompts-roles-plan.md`（§2、§5 P1）

## Global Constraints

- 任务数：规划提示自己说明（首次 1–7、重新规划 1–6、设计 1–8），`intent_prompt` 不再写数量。
- 规划者的称呼统一为「KiroCrew 规划者」；工作流设计会话为「KiroCrew 规划者（工作流设计）」。
- 工具：不再写默认组合（「Kiro 分析、Claude 编码、Codex 审查、OpenCode 交付」）；改为「从执行环境中 available 为 true 的工具按任务性质选择；
  审查类任务使用与被审查代码不同的工具」。
- 交付：Agent 不自行推送分支或创建 PR / MR；平台提交候选、审查通过后由用户发布。
- 结论：缺陷用 `changes_requested`，`BLOCKED` / `blocked` 只用于缺输入、认证或权限。
- 交接内容清单（源码基线、改动文件、执行的命令与退出码、验证范围、未解决问题与下一步）写进 `instructions.md`。
- 纠错要求只发给被安排修复的任务（`retry` 的失败任务、`rework` 的目标任务），内容为决定与失败摘要（错误 ≤1500、发现 ≤10 条）。

## Review Focus

1. **旧 Worker**：平台新增的派发字段不影响旧 Worker；新 Worker 收到旧平台的请求时外壳照旧可用（`test_an_old_platform_dispatch_still_reads_well`）。
2. **纠错不外漏**：返工目标之后的审查任务不再收到「纠错后的重新执行」（`test_only_the_reworked_task_is_told_to_repair`）。
3. **规划规则一致**：首次规划与重新规划都含契约、门禁、preview.json、.gitignore、工具选择依据（`test_both_plans_carry_the_same_rules`）。
4. **长度**：模型很多时首次规划提示仍在 8000 字符内（`test_the_first_plan_fits_with_many_models`）。
5. **模板**：内置模板的每个步骤都有 `kind` 与验收项，不再使用 OpenCode，审查步骤不说「报告 BLOCKED」（`test_built_in_templates_carry_a_contract`）。
