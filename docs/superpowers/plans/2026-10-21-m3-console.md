# M3-5 控制台：服务端过滤、全文搜索、分页与代码改动 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 控制台与 Coding Agent 能按状态、仓库、分支、阶段、工具、客户端、提交者、时间与全文找到会话，列表服务端分页；详情能看每次候选的代码改动。

**Architecture:** 新模块 `octopus/listing.py` 承担会话的匹配与分页（`Service.runs` 调用它）；Worker 的 `/candidate` 加 `mode: diff`，平台 `GET /v1/runs/<id>/attempts/<attempt>/diff` 转发；控制台侧栏改为 `useInfiniteQuery`，筛选写进地址栏。

**Tech Stack:** Python 3.12 标准库 + SQLite，React + TypeScript（TanStack Query），unittest、vitest。

**Spec:** `docs/superpowers/specs/2026-10-21-m3-console-design.md`（D56）

## Global Constraints

- 不带 `page` 的 `GET /v1/runs` 照旧返回数组（旧版控制台、MCP、脚本不受影响）。
- 访问控制不变：逐行 `run_access`；`all=1` 仍只对管理员生效。
- 使用者看到的文字是中文；错误只写原因（D53）。
- diff 只读、不移动分支；截断上限 200 KB 或 4000 行。

## Review Focus

- **翻页期间有新会话创建**：游标按（创建时间, ID）向更早翻，已翻过的条目不重复，也不遗漏（Task 1 测试）。
- **仓库写法不同**：`git@github.com:o/r` 的会话能被 `repo=github.com/o/r` 与 `repo=O/R` 找到；新建项目不命中（Task 1 测试）。
- **全文搜索命中任务说明与结论**：只在任务 prompt 或最近一次结论摘要里出现的词也能找到会话（Task 1 测试）。
- **选中的会话不在已加载的页里**：不误报「不可访问」（Task 3 测试）。
- **没有候选的 Attempt、旧 Worker**：404 `no_candidate` / 409 说明，不是 500（Task 4 测试）。
