# 运行中补充说明与释放对话（D46 P5b）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 运行中的任务可补充说明（KiroCrew steer）；删除会话时释放其可续接的对话（release）。

**Architecture:** Worker `POST /steer {run_id, attempt_id, message, mode}` 核对 Attempt 属于本会话后调 `/api/spawn/{native_id}/steer`；`_control` 删除时调 `/api/spawn/{conversation}/release`。平台 `Service.steer` 校验权限与任务状态，经 Worker 转发，写审计与时间线；路由、OpenAPI、MCP 工具、控制台对话框。

**Tech Stack:** Python 3.12 标准库、unittest；React + TypeScript + vitest。

**Spec:** `docs/superpowers/specs/2026-10-19-steer-design.md`

## Global Constraints

- 说明 1–4000 字符；`mode` 只能 `interrupt` / `follow_up`，默认 `interrupt`。
- 权限：`may_publish`（创建者、Team owner、管理员）；已归档 Team 拒绝（`team_archived`）。
- 只对当前 Attempt 状态为 `running` / `waiting_approval` 且有原生 ID 的任务。
- 时间线 `task.steered`：说明前 500 字符、方式、任务。

## Review Focus

- 另一个会话的 Attempt ID：Worker 拒绝（Task 1 `test_another_sessions_attempt_is_refused`）。
- KiroCrew 409 / 503：分别转为「任务已不在运行」「稍后再试」，不是 502（Task 1 `test_refusals_are_said_as_they_are`）。
- 删除时 release 失败：删除照常完成（Task 1 `test_a_failing_release_never_stops_the_delete`）。
- 已完成的任务：平台拒绝，不调用 Worker（Task 2 `test_only_a_running_task_is_steered`）。
- 旧 Worker（404）：说明执行环境尚未支持（Task 2 `test_an_older_worker_says_so`）。
