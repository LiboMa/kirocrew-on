# MVP 0.2.0 P1 打底：实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为集群版与一键安装打底，同时不改变任何用户可见的行为。范围是设计 §15 P1 的 ①–⑪。

**Architecture:**
- 身份与登记：
  - 新边界的身份改由控制面分配：`boundary_id` 与全局 UID，旧边界照旧；
  - 修好两处登记不一致；
  - 人工接入改用一次性接入码（N），Token 不再经过 SSM；
  - Engine 的单主改为可替换的租约接口。
- 发布物：一个 wheel，加上签名的版本清单。
- 安装：脚本按架构下载依赖。
- 控制面：
  - Worker 的健康信息补上容量字段；
  - 平台按分钟产出指标。
- 需要 AWS 资源或排空 EC2 的三项（⑤ Litestream、⑨ 指标上云、⑩ KiroCrew 升级），在本地完成代码、测试与手册；云上验证等前提满足再做，各任务里写明。

**Tech Stack:** Python 3.12 标准库（项目不引入 boto3）、SQLite 迁移（`octopus/migrations.py`）、React 控制台（`web/`）、bash 安装脚本（`deploy/install/`、`deploy/aws/deploy.sh`）、nginx。

**Spec:**
- `docs/superpowers/specs/2026-10-25-mvp-0.2.0-deployment-and-worker-pool-design.md`：§5.3、§6.7、§7.2、§10、§12、§15 P1、§18、附录 A；
- `docs/superpowers/specs/2026-10-24-worker-enrollment-design.md`（N）：§3–§6；
- 路线图 `docs/superpowers/plans/2026-10-26-mvp-0.2.0-roadmap.md`。

## Global Constraints

- **用户体验不变**：P1 只有一处可见变化，就是管理员「登记 Worker」多出「用接入码」（设计 §15 P1）。其余都是增量，或者带开关。
- **身份**：
  - `boundary_id` 只从渲染出的 Worker 配置读，不从用户卷读（CE3，硬性要求）；
  - 配置里没有 `boundary_id` 的旧边界照旧，健康信息不变（设计 §7.2）。
- **全局 UID / GID** = 100000 + 序号，永不复用；自助边界的名字为 `u<序号>`（S9）。
- **登记唯一性**：`boundary` 不得与任何 Worker 相同，包括已停用、已退役的（CE9，硬性要求）。
- **接入码**：
  - 只有管理员能签发；默认 30 min，最长 24 h（S6、§6.7）；
  - 平台只存 SHA-256；
  - 无效时直接返回 404，按 `CloudFront-Viewer-Address` 限流，而且这一步之前不调 Worker（CE6）；
  - 登记规则与 `POST /v1/workers` 完全相同（N §2）。
- **权限**：不给 m1 的实例角色加任何 AWS 写权限（设计 §5.3 第 10 条）。Litestream 只在没有 Agent 的临时控制面主机上验证（S31）。
- **依赖**：不新增 Python 运行依赖；发布物的签名在本地用 openssl 验证（KMS 签名留给 CI）。
- **用语**：回复与文档用中文；代码注释用英文，风格同现有代码；不出现参照站点的名字。
- **流程**：每项先写失败的测试（`superpowers:test-driven-development`）；部署前跑完整的 `tools/regress.sh`；`git push --no-verify` 之前，先在 clean clone 上跑 git-defender。

## Review Focus

- **旧边界不受影响**：配置里没有 `boundary_id` 的 Worker，健康信息里的 `boundary` 必须与改动前逐字节相同。否则引擎会把所有现有 Worker 当作被换了主机，原生入口全部返回 409。归 Task 2 的测试。
- **接入码被重放、并发使用、过期后使用**：同一码两个请求同时到达，只能有一个成功；另一个返回 404，而且不能留下第二个 Worker。归 Task 6。
- **接入码登记绕过登记规则**：接入码指定的空间与 Worker `/health` 报的身份冲突时（已登记的边界、宿主账号复用、平台主机账号），要与 `POST /v1/workers` 一样拒绝。归 Task 6，复用 Task 1 抽出的校验函数。
- **UID 序号回收**：边界释放后，新分配不得复用它的序号与 UID；并发分配不得重号。归 Task 3。
- **在 x86 主机上照旧安装**：架构检测改动后，现有 EC2（x86_64）上的 `al2023.sh` 必须仍然选中 x64 的 Node 和 kiro-cli。归 Task 8。
