# M2 剩余：Request、按仓库准入、映射偏好 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 每次提交登记一个 Request。准入可按个人 / Team 的仓库规则决定，平台默认改为先确认。个人 / Team 的映射偏好交给 KiroCrew 规划者参考。

**Architecture:**
- 迁移 9 新增 `requests` 与 `policies` 两张表，`runs` 加 `request_id`。
- `octopus/requests.py` 登记和读取 Request；`octopus/policies.py` 管理规则，并给出两样东西：准入的判定（模式和依据），以及一次提交适用的偏好。
- `Service.start` 在建会话的同一事务里登记 Request，用规则决定准入，把偏好快照写进会话；规划与重新规划的提示多一节偏好；映射来源标出按偏好。

**Tech Stack:** Python 3.12 标准库 + SQLite（`octopus/`），React + TypeScript（`web/`），unittest、vitest。

**Spec:** `docs/superpowers/specs/2026-10-21-m2-rest-design.md`（D55，§6 是负责人 2026-10-21 的三项决定）

## Global Constraints

- 使用者看到的文字是中文；提示只写原因，以及「请平台管理员……」或「请 Team owner……」，不给运维命令（D53）。
- 平台不内置默认工具链：偏好只是规划者的参考，不替换需求中指定的（D45）、Workflow / 模板写定的工具，也不是失败时的回退链（负责人 no-hardcoded-chains）。
- 默认准入：`Config.default_admission` 改为 `"confirm"`。`Service.__init__` 的参数默认值保持 `"auto"`，测试替身照旧。
- Worker 的任务说明不超过 8000 字符：首次规划与重新规划的提示，在各输入都取上限时仍须满足。
- Team 的规则只有 Team owner 和管理员能建、能删；个人规则只有本人。每次增删写审计（`policy.create` / `policy.delete`）。
- Request 先一对一：一次提交对应一个 Request 和一个 Session；表结构允许一对多，本期不做「重新发起」。
- 旧会话没有 Request：视图里 `request` 为 `null`，不补登记。

## Review Focus

- **同一 `request_id` 重复提交**：返回原有的 Session，`requests` 表不多出一行（Task 1 测试）。
- **仓库写法不同**：`https://github.com/o/r.git`、`git@github.com:o/r`、`https://github.com/O/R` 都应命中规则 `github.com/o/r`（Task 2 测试）。
- **新建项目的会话（没有仓库）**：任何仓库规则都不命中，走平台默认（Task 2 测试）。
- **非 owner 改 Team 规则、非成员读 Team 规则**：403 / 404；已归档的 Team 不能新增规则（Task 2 测试）。
- **偏好很多、很长**：规划提示截断这一节，首次规划与重新规划在最坏情况下都不超过上限（Task 3 测试）。

**Interfaces:**
- 表 `policies(id TEXT PK, kind TEXT NOT NULL CHECK(kind IN ('admission','mapping')), owner_id TEXT REFERENCES users(id), team_id TEXT REFERENCES teams(id), rule TEXT NOT NULL, created_by TEXT NOT NULL REFERENCES users(id), created REAL NOT NULL, CHECK((owner_id IS NULL) != (team_id IS NULL)))`，放在迁移 9 里。Task 1 已建表时，本任务只用它。
- Produces:
  - `policies.repo_of(source: dict) -> str | None`：`host/owner/repo`，小写，去掉 `.git`；`https`、`ssh`、`user@host:path` 三种写法同一结果；`type == "new"` 时为 `None`。

  - `Service.create_policy(actor, body) -> dict`。body 为 `{"kind", "scope": "personal" | "team", "team_id"?, "rule"}`，校验 kind 与 rule 的形状，以及作用域权限：Team 须是 owner 或管理员，且 Team 未归档（用 `active_team`）。
  - `Service.policies(actor, team_id=None) -> list[dict]`：本人的个人规则，加上本人所在 Team 的规则。
  - `Service.delete_policy(actor, policy_id) -> dict`。
