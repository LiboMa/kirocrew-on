# 恢复阶梯第 2 期：重新规划（D41） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 协调者可以决定 `replan`：平台删除失败的任务及其后的任务（Attempt 留作历史），插入一个 Kiro 重新规划任务，其结果经 `planning.expand` 校验后追加为新的任务；每个会话至多一次。

**Architecture:** `recovery.Coordinator` 接受 `replan`；`recovery.finish` 在目标处理之前调用 `_replan` 生效；`planning.replan_step` 构造提示，`planning.expand(..., replan=True)` 追加任务并避开所有已有 Attempt 的任务 ID；Engine 在 `replan-1` 验收时调用 `expand`；`domain.mapping` 与控制台纠错记录显示重新规划。

**Tech Stack:** Python 3 标准库、React + TypeScript。

**Spec:** `docs/superpowers/specs/2026-10-15-replan-design.md`

## Global Constraints

- 决定：`{"action": "replan", "reason", "instructions"}`；`target_task_id` 可省略。
- 拒绝（会话 `blocked`，`error` 前缀「协调者重新规划的决定未通过核对：」）：已重新规划过（快照 `replan` 存在）；工作流设计会话；失败的是规划任务本身（`plan` 或 `replan-*`）。
- 生效：删除 `ordinal ≥ 失败任务` 的任务（变更记录 `task.replaced`）；插入 `replan-1`（`kind` 不设，Kiro / auto，`ordinal` = 失败任务的 `ordinal`）；快照 `replan = {task, applied: false, replaced: [{id, name}], reason, instructions, recovery}`；修订 `recovered`「自动纠错：重新规划，替换「a、b」（原因）」。
- `replan-1` 的提示包含：用户需求、规划补全的 `intent` / `summary`、已验收任务（D40 交接格式：名称、类别、结论摘要）、被替换的任务、失败原因（失败 Attempt 的 `error`）、协调者的原因与要求；要求只规划剩余工作、1–6 个任务、每个任务带契约，输出与首次规划相同的 JSON。
- `expand(..., replan=True)`：校验同首次规划；新任务 ID 避开 `tasks` 与 `attempts` 中的所有 `task_id`；`replan.applied = true`，`replan.tasks = [...]`；修订 `planned`「重新规划：追加 N 个任务」。
- 映射来源：`replan-1` →「平台：重新规划（Kiro）」；`replan.tasks` →「KiroCrew 重新规划」。
- 协调者上下文 `environment.replanned`（布尔）。

## Review Focus

1. **历史不混**：被替换的任务与新任务同名（如都叫 `code`）时，新任务的 ID 改为不冲突的，旧 Attempt 不出现在新任务下。（`test_new_tasks_do_not_take_the_ids_of_replaced_ones`）
2. **只一次**：第二次 `replan` 被拒，会话 `blocked` 并写明原因。（`test_a_second_replan_is_refused`）
3. **规划失败**：`replan-1` 的结果不是有效计划时 `blocked`（`contract`），不追加任何任务。（`test_an_invalid_replan_blocks_the_replan_task`）
4. **已验收保留**：重新规划之前已验收的任务及其 Attempt 不变，新任务排在它们之后。（`test_a_replan_replaces_the_failed_and_later_tasks`）
5. **上下文**：`replan-1` 的提示包含已验收任务的结论与失败原因。（同上）
