# KiroCrew ON MVP 0.1.1：版本说明

日期：2026-10-24　·　分支 `feat/mvp-0.1.1`（PR #5），基于 main `fe49f81`（EC2 当时运行 `12fbd9f`）　·　HTML 版：[`docs/KiroCrew-ON-MVP-0.1.1.html`](KiroCrew-ON-MVP-0.1.1.html)

产品是什么、给谁用、整体流程，见 [MVP 0.1.0：产品、流程与架构](MVP-0.1.0.md)。本文只写 0.1.1 相对 0.1.0 的变化。

## 1．这一版做了什么

| 方面 | 变化 |
|---|---|
| **前端优化** | 控制台整体改版：左侧分组导航、浅色 / 深色主题、新标志；管理与「我的设置」的列表都改成表格，新增、修改、危险操作都在对话框里完成 |
| **Token 重新生成** | 已有的 API Token 可以换一个新值，名称和权限不变，旧值立即失效 |
| **在 KiroCrew 聊天里协作（D73 补充）** | 续作时提醒聊天里改过的文件；聊天里新建的文件也会被认出，续作前一并提交 |
| **门禁与提示（D57 补充）** | 提示写清发生了什么、是谁的问题、建议怎么做；门禁显示中文名，检查分为必过和建议两类；打码与审查撤回做了多处修正 |
| **性能** | 会话列表的数据量减少约一半，gzip 后约减少 70% |
| **可用性** | 对话框关闭后，焦点回到打开它的按钮；手机上行操作收进「⋯」 |

## 2．前端优化

### 2.1 导航与页头

- 左侧导航分三组：**工作台**（会话）、**管理**（只有管理员看得到）、**我的设置**。每个条目都是链接，可以新开标签页或收藏。
- 导航底部是「深色模式」和「收起导航」，这两个设置都记在浏览器里。
  - 没有选过主题时，跟随系统设置。
  - 收起后只显示图标。
- 页头内容随页面变化：
  - 会话页显示开发空间切换；
  - 管理和设置页显示当前位置，例如「管理 / 用户」；
  - 右侧固定是「新建开发」和账户菜单（修改密码、经典控制台、退出登录）。
- 窄屏上的入口：
  - 1024 像素以下，从「打开导航」打开导航；
  - 768 像素以下，从「打开会话列表」打开会话列表。
- 标志换成四个方块拼成的 K，浏览器标签页的图标同步更换。

### 2.2 列表页

管理与「我的设置」的列表页结构统一，由上到下是：

- **标题、说明和主操作**，例如「新建 Token」「新建用户」「登记 Worker」；
- **工具栏**：搜索、刷新，右侧显示数量；
- **表格**：行尾放常用操作（图标加文字），其余的收进「⋯」，危险操作标红。手机上所有行操作都收进「⋯」，不并排放按钮；
- **空列表**：说明下一步做什么；搜索没有结果时，说明没找到什么。

「管理 › 概览」改为统计卡片，点一张卡片进入对应的管理页。

### 2.3 操作都在对话框里完成

页面上不再有编辑用的输入框，只保留搜索框。覆盖的页面：

| 页面 | 对话框 |
|---|---|
| API 与 Coding Agent 接入 | 新建 Token、重新生成、撤销 |
| 管理 › 用户 | 新建用户、重设密码、加入 Team、改执行环境、查看与撤销 Token、设为 / 取消管理员、停用 / 启用 |
| 管理 › 执行环境 | 登记 Worker、编辑（名称、连接）、分配到空间、设为共享 / 改回专属、停用、退役 |
| Team | 新建 Team、改名、添加成员、更换执行环境、归档 / 恢复、改角色、移出、退出 Team |
| 代码仓库凭证 | 添加凭证（分「是什么」「能访问哪些仓库」「Token」三节）、仓库范围、更换 Token、停用 / 启用、删除 |
| 映射偏好 | 新增规则、编辑、删除 |
| 并发上限 | 修改、移除上限、单独设置上限 |
| 修改密码 | 修改密码 |

对话框的规则：

- 一个对话框只做一件事。标题用动词，提交按钮写出结果，提示条用同一个词，例如「重新生成 Token」→「重新生成」→「已重新生成 Token X」。
- 危险操作先写明后果。例如停用用户：此人立即不能登录、全部 Token 失效；进行中的会话照常执行，但不能再用此人的个人仓库凭证。
- 失败时对话框不关闭，在框内显示服务器给的原因。
- 新增或修改的行高亮一次，删除的行淡出。系统设置为「减少动态效果」时，不播放动画。
- 一次性的密钥（新建或重新生成的 Token）只在那一屏显示一次，配「复制」和「我已保存」。

## 3．Token 重新生成

- **入口**：控制台「API 与 Coding Agent 接入」每行的「重新生成」，或接口 `POST /v1/tokens/<id>/regenerate`。
- **结果**：同一条 Token 换一个新值，只显示一次；旧值立即失效（返回 401），用旧值打开的状态流也会断开。
- **有效期**：默认保持原到期时间，也可以改为从现在起 7 天、30 天、365 天或永不过期。带 admin 权限的 Token 最长 30 天。
- **限制**：
  - 当前登录正在用的那枚返回 `409 token_in_use`，列表里标「当前登录」，不提供重新生成和撤销；
  - 发起请求的 Token 的权限要覆盖目标 Token 的权限，否则返回 403。例如只有 manage 权限的 Token，不能拿到同一账号 admin Token 的新值。

## 4．在 KiroCrew 聊天里协作（D73 补充）

- **续作时提醒**：续作对话框读取 `GET /v1/runs/<id>/chat-changes`，在需求下方列出聊天里改过、还没提交的文件，提示你同步修改需求。只提醒、不拦截，读取失败时不显示。
- **认出新建的文件**：Worker 的 `/candidate check` 可选 `untracked`，聊天里新建的文件也会在续作前提交为「对话中的改动」。平台检查自己留下的产物不算在内，判断依据是 `run/untracked-seen.json`，它在审查开始、候选提交、检查结束时重写。

## 5．门禁与提示（D57 补充）

- **提示**：写清发生了什么、是谁的问题、建议怎么做；门禁显示中文名；诊断等待批准、预算拒绝重试时，说清是哪一项。
- **检查分类**：检查分为必过和建议两类，续作原样带回的检查保持原来的分类。
- **打码**：
  - 露出的首尾不切断转义；
  - 紧挨着的密钥合成一处；
  - 控制台的会话观察由平台再打码一次。
- **审查撤回**：撤回审查者的改动之前，先存一份 `tracked.patch`。
- **阶段放宽（D69）**：审查者的改动没能撤回的尝试（`review_bound` 失败），不按阶段放宽。

## 6．性能：会话列表瘦身

- **改了什么**：`GET /v1/runs?view=list` 只返回列表用得到的内容。
  - 需求只留前 200 字；
  - 规划去掉说明文字；
  - 不再返回、也不再计算用量、知识、凭证可用性与核验结果。
- **不受影响**：会话页 `GET /v1/runs/<id>` 照旧返回完整内容。
- **效果**：按 EC2 上 50 行的数据估算，未压缩从 223 KB 降到 119 KB，gzip 后从 53 KB 降到 15 KB；服务器也不再为每一行读取全部尝试记录。
- **核对过的使用方**：侧栏、空状态页、MCP `octopus_runs`、CLI `search`，以及从列表行打开的对话框，都不用被去掉的字段。

## 7．升级须知

- **需要一起部署**：平台和 Worker 要一起部署，因为续作检查新文件用到 Worker 的新参数 `untracked`。`deploy.sh push` 会一起更新。
- **接口变化**（都向后兼容）：
  - 新增 `POST /v1/tokens/<id>/regenerate`；
  - 新增 `GET /v1/runs/<id>/chat-changes`；
  - `GET /v1/tokens` 每条多了 `current`；
  - `view=list` 的字段变少（见第 6 节）。自己写的脚本如果从列表里读用量或完整需求，要改为读会话详情。
- **不需要迁移数据**。
